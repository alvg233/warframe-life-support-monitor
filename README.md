# Warframe 生存任务 维生系统监控 · 钉钉提醒（Screen OCR Alert）

Warframe / 星际战甲 生存任务挂机辅助：定时识别屏幕左上角的「维生系统」（氧气）百分比与任务计时，
低于阈值自动记录、截图并通过钉钉群机器人推送，支持氧气归零或时间到达时自动急停（暂停游戏）。

> 关键词：Warframe、星际战甲、生存任务、维生系统、氧气、挂机监测、屏幕识别 OCR、钉钉提醒、
> 自动急停、Warframe survival life support monitor、OCR alert、DingTalk webhook。

> 本工具只做画面识别与本机操作，不上传任何数据；钉钉消息只发到你自己配置的群机器人。

## 功能

| 能力 | 说明 |
| --- | --- |
| 画面识别 | 定时截取游戏窗口内的指定区域，识别百分比数值；支持窗口截图与整屏截图两种通道 |
| 双阈值 | 预警线（记录 + 截图）与报警线（额外钉钉推送），只按"穿越"触发，避免持续刷屏 |
| 重提醒 | 持续低于报警线时按间隔重复提醒（默认 30 分钟），并可带最新截图 |
| 速率校验 | 单次识别下降超过 1%/1.5 秒视为错读，自动重读并要求读数一致才采纳 |
| 自动校准 | 区域随窗口缩放失效时，在搜索区内自动定位百分比行并收敛识别框 |
| 急停 | 数值归零或时间到达时切到游戏前台、点击窗口、按 ESC，并连续识别确认已离开战斗界面 |
| 悬浮窗 | 主窗口最小化时显示数值与时间，置顶、半透明、鼠标穿透 |
| 本地记录 | 报警事件表、采样记录、技术日志、截图，按天归档并自动清理 |
| 诊断包 | 一键打包日志与脱敏配置，便于反馈问题（完全本地生成） |

## 快速开始

下载安装包：[Gitee 发行版](https://gitee.com/alvg233/warframe-life-support-monitor/releases) ·
[GitHub Releases](https://github.com/alvg233/warframe-life-support-monitor/releases)

1. 运行 `Warframe-LifeSupport-Monitor-Setup-x.y.z.exe`，按向导完成安装（可选择安装路径、是否创建桌面与开始菜单快捷方式，默认创建）。
2. 首次启动进入设置向导：
   - **选择窗口**：在列表中选中 `Warframe`，程序记录窗口标题与进程名。
   - **框选区域**：拖出矩形覆盖「维生系统」标签下方那一行百分比（含 `%` 号）。
   - **设置阈值**：默认预警线 50、报警线 35，按需修改；预警线必须高于报警线。
   - **填写钉钉**：粘贴群机器人 Webhook；使用加签时同时填密钥；可先发送测试消息。
3. 回到主界面点击「开始监控」。游戏需使用无边框窗口或窗口化模式（独占全屏无法截取画面）。

## 界面与操作

主界面显示当前数值、状态（正常 / 预警 / 报警 / 未知）、任务时间，以及事件提示行。
数值异常时，事件行会给出原因与建议，例如区域未框好、游戏处于菜单、截图通道不匹配等。

「高级设置」包含五个页签：

| 页签 | 内容 |
| --- | --- |
| 检测区域与判定 | 区域坐标、自动校准、数字解析方式、预警线/报警线、重提醒间隔 |
| 急停 | 触发条件、时间区域、点击位置、按键次数、验证次数、自动恢复监控 |
| 截图存档 | 截图开关、通道（游戏窗口 / 整屏）、窗口标题与进程名、保存目录、保留天数 |
| 钉钉通知 | Webhook、加签密钥、关键词、@ 成员、超时与每分钟上限、消息模板 |
| 运行与日志 | 启动后自动监控、进程优先级、区域边框、采样日志、悬浮窗、诊断包导出 |

## 急停

急停用于在数值归零或时间到达时把游戏切到前台并暂停，避免继续挂机。

执行流程：

1. 将游戏窗口切换到前台（必要时用 AttachThreadInput 绕过前台锁定）。
2. 向游戏客户区发送一次鼠标点击（部分游戏需要真实点击后才接收键盘）。
3. 发送 ESC（次数可配置）。
4. 连续识别若干次（默认 5 次，间隔 0.6 秒）：
   - 全部识别不到合法数值 → **急停成功**，随后停止监控；
   - 任意一次读到数值 → 记为 **未确认**，原因保留在事件行。

触发条件可多选，也可都不选：

- **百分比归零**：主读数 ≤ `zero_threshold`（默认 0.5）。
- **时间到达**：读取独立的时间区域（`mm:ss`），达到 `elapsed_minutes` 分钟。

时间读数有合理性校验：只允许缓慢递增，明显跳变先挂起、下一轮同值才采纳；
"少一位"的读数（例如 226:11 被读成 26:11）直接判为误读，不回退。

勾选「急停后等待下一局并自动恢复监控」时，急停成功后程序在后台等待计时器归零，
检测到新一局自动恢复监控；等待期间仅在计时器画面变化时才执行识别。

## 悬浮窗

勾选「最小化时显示悬浮窗」后，主窗口最小化且正在监控时，在选定位置显示当前百分比与任务时间。
窗口置顶、半透明、鼠标穿透、不抢焦点，可在设置中调整位置、透明度与字号。

## 数据与日志

数据目录：`%APPDATA%\ScreenOcrAlert`（若 exe 同目录存在 `portable.txt`，则改为程序目录）。

| 路径 | 内容 |
| --- | --- |
| `config.json` | 配置；保存前自动保留 `.bak` |
| `logs\events.jsonl` | 业务事件：跌破预警线、跌破报警线、重提醒、恢复正常、急停 |
| `logs\samples.log` | 每次采样一行：`时间 + 数值`，识别失败记为 `fail` |
| `logs\app.log` | 启动、停止、报警、发送失败等关键事件（按大小轮转） |
| `logs\startup.log` | 启动过程跟踪，用于排查无法启动的问题 |
| `logs\crash.log` | 崩溃堆栈（faulthandler） |
| `logs\diagnostics\` | 手动或异常时生成的诊断包（zip） |
| `snapshots\日期\` | 截图，文件名即实际时间，报警截图带 `_EX` 后缀 |

诊断包内含日志尾部、脱敏后的配置（Webhook / 密钥 / 签名打码）、系统与依赖版本、最近三张截图。
包在本地生成，不会自动上传。

## 常见问题

**识别不到数值**
在「检测区域与判定」点击「自动校准」；确认游戏不在菜单或加载画面；确认截图通道为「游戏窗口」。

**截图全黑**
游戏为独占全屏时无法截取窗口画面，请改为无边框窗口，或把截图通道设为「整屏」。

**钉钉没有收到**
先在「钉钉通知」点击测试；若使用加签，确认密钥与 Webhook 匹配；技术日志会记录 errcode。

**急停没有按到游戏**
部分游戏需要真实鼠标点击才接收键盘，确认「切前台后先点一下游戏窗口」已勾选；
点击位置默认在左上角「生存」附近（比例 0.05 / 0.15），避免点到界面按钮。

**安装或启动被系统拦截**
程序未购买代码签名证书，属于未签名程序的通用提示，选择「更多信息 → 仍要运行」即可。
